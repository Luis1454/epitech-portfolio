Introduction

This documentation describes the functionality of the R-Type server, which handles multiplayer game sessions, manages game state, and communicates with clients using UDP.

Key Features

  • UDP-based network communication
  • Real-time game state management
  • Entity Component System (ECS) for game logic
  • Scalable and modular architecture

Server Architecture

The server is built using an Entity Component System (ECS) framework to manage game entities and their behaviors. The main components of the server are:

  • UdpServer: Manages UDP communication with clients.
  • ECS: Manages entities, components, and systems.
  • Parser: Parses incoming data and handles commands.
  • Track: Manages game levels and tracks.

UdpServer Class

The UdpServer class handles the UDP server. Here are its main features:

Constructor

UdpServer(uint16_t port)

Initializes the server on the specified port. Sets up the socket and performs the binding.

Main Methods

  • void start(): Starts the server in a separate thread.
  • void stop(): Stops the server.
  • void run(): The main server loop that handles packet reception and processing.
  • void process_packet(const std::vector<uint8_t>& packet): Processes received packets.

Server Workflow

  1. The server is initialized with a specific port.
  2. The start() method launches the server in a separate thread.
  3. In the main loop (run()), the server continuously waits for UDP packets.
  4. When a packet is received, it is processed by process_packet().
  5. The server can handle two types of packets:
    • Type 0x01: Position data (X, Y, direction, speed)
    • Type 0x02: Client username
  6. After processing, the server echoes the packet back to the client.

Packet Format

Position Packet (Type 0x01)

[0]     : Type (0x01)
[1-2]   : ID (2 bytes)
[3-4]   : Position X (12 bits)
[4-5]   : Position Y (12 bits)
[6]     : Direction
[7]     : Speed

Username Packet (Type 0x02)

[0]     : Type (0x02)
[1-2]   : ID (2 bytes)
[3-17]  : Username (15 characters max)

Error Handling

The server handles the following errors:

  • Initialization errors (socket creation, binding)
  • Packet reception errors
  • Response sending errors
  • Packets that are too short or of unknown type

Compatibility

The code includes preprocessor directives to ensure compatibility between Windows and Unix/Linux systems.

Example Code Snippets

Initializing the Server

#include "UdpServer.hpp"
#include "ECS/ECS.hpp"
#include "Parser.hpp"
#include "Track.hpp"

int main() {
    UdpServer server(8080);
    server.start();

    // Main game loop
    while (true) {
        server.run();
    }

    server.stop();
    return 0;
}
