What is ECS?

An Entity Component System (ECS) is a design pattern commonly used in game development for organizing complex systems. It separates game logic into three main parts:

  • Entities: Unique IDs representing game objects.
  • Components: Data associated with entities (e.g., position, velocity).
  • Systems: Logic that operates on entities with specific components.

How ECS Works

The ECS pattern decouples game objects from behavior, making your code modular and easier to maintain.

1. Entities

Entities are simple IDs or objects that represent game objects (e.g., a player, enemy, projectile). They do not contain data or behavior directly.

// Example Entity in C++
int playerEntity = createEntity();

2. Components

Components hold the data for entities. For example:

  • Position (x, y)
  • Velocity (speed, direction)
  • Sprite (graphic to render)
  • Health (current and maximum health)
  • State (e.g., alive, dead, invincible)
// Example Component: Position
struct Position {
    float x, y;
};

3. Systems

Systems operate on entities that have specific components. For example:

  • Movement System updates positions based on velocity.
  • Render System draws sprites based on position.
  • Collision System handles collisions between entities.
  • State Control System manages entity states (e.g., alive, dead).
// Example System: Movement
void MovementSystem(std::vector entities, std::map velocities, std::map& positions) {
    for (auto& entity : entities) {
        positions[entity].x += velocities[entity].x;
        positions[entity].y += velocities[entity].y;
    }
}

Why Use ECS?

  • Separation of Concerns: Data and logic are cleanly separated.
  • Performance: Systems iterate efficiently over components.
  • Modularity: Adding new systems or components is easy.

Putting It Together

Here is how you might use ECS in a game loop:

int main() {
    // Create Entities
    int player = createEntity();
    Position playerPos = {100, 200};
    Velocity playerVel = {5, 0};

    // Add Components
    addComponent(player, playerPos);
    addComponent(player, playerVel);

    // Run Systems
    while (gameRunning) {
        MovementSystem(entities, velocities, positions);
        RenderSystem(entities, positions, sprites);
    }

    return 0;
}

Code Structure

The ECS code is organized into several key files and directories:

  • Components: Defines data structures for entities.
    • Component.cpp / Component.hpp: Base class for components.
    • Position.cpp / Position.hpp: Manages position data.
    • Velocity.cpp / Velocity.hpp: Handles velocity data.
    • Health.cpp / Health.hpp: Manages health data.
    • State.cpp / State.hpp: Manages state data.
    • Enemy.cpp / Enemy.hpp: Represents enemy entities.
    • Boss.cpp / Boss.hpp: Represents boss entities.
  • Entities: Base class for all entities.
    • Entity.cpp / Entity.hpp
  • Systems: Defines behaviors and processes.
    • Gravity.cpp / Gravity.hpp: Implements gravity logic.
    • Motion.cpp / Motion.hpp: Handles motion updates.
    • Collision.cpp / Collision.hpp: Manages collision detection and response.
    • StateControl.cpp / StateControl.hpp: Manages entity states.
    • System.cpp / System.hpp: Base class for systems.
  • Core Files: Core ECS management.
    • ECS.cpp / ECS.hpp
    • Sparse.cpp / Sparse.hpp: Sparse array implementation for efficient data storage.

Updating the ECS

void ECS::update() {
    std::lock_guard lock(_mutex);
    for (auto &system : _systems) {
        if (system.second != nullptr) {
            system.second->setRefTime(_lastMsgTime);
            system.second->setDeltaTime(_dt);
            system.second->update();
        }
    }
    std::chrono::system_clock::time_point now = std::chrono::system_clock::now();
    _dt = std::chrono::duration_cast>(now - _lastUpdate).count();
    _lastUpdate = now;
}

Handling User Input

void Menu::handleEvents(UdpClient &client) {
    sf::Event event;

    while (_window.pollEvent(event)) {
        if (event.type == sf::Event::Closed)
            _window.close();

        if (event.type == sf::Event::KeyPressed) {
            if (event.key.code == sf::Keyboard::Space) {
                Protocol protocol;
                std::vector fields;
                std::cout << "Space key pressed" << std::endl;

                protocol.resizeBuffer(8);
                fields.push_back({9, 8});
                fields.push_back({(uint16_t)_ecs.getClientId(), 16});
                protocol.setBuffer(protocol.createPacket(fields));
                protocol.runRequest(_ecs);
                fields = {};
                for (auto &b : protocol.getBuffer())
                    fields.push_back({b, 8});
                client.addRequest(fields);
            }

            if (event.key.code == sf::Keyboard::Escape)
                _window.close();
        }
        if (event.type == sf::Event::MouseButtonPressed) {
            auto mousePos = sf::Mouse::getPosition(_window);

            if (gameButton.getGlobalBounds().contains(static_cast(mousePos)))
                _game.run(_window, client);
            if (settingsButton.getGlobalBounds().contains(static_cast(mousePos)))
                _setting.run(_window);
            if (StoryButton.getGlobalBounds().contains(static_cast(mousePos)))
                _story.run(_window);
        }
    }
}

Conclusion

ECS is a powerful architecture for game development. By separating data and logic, it enables modularity, performance, and flexibility in game design.
